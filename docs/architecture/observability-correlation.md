# Observability and correlation contract

RAMALS keeps business correlation separate from execution tracing:

- `interactionId`: canonical lowercase UUIDv7 generated by the browser for one meaningful user action and preserved across safe retries.
- `traceId`: OpenTelemetry/W3C execution identifier; a retry may create a new trace.
- `spanId`: one operation within a trace, including JDBC operations.
- `requestId`: UUID scoped to one HTTP request.

## HTTP contract

The browser sends `X-Interaction-ID`. Spring validates UUID version, variant, and canonical lowercase representation. If the header is omitted, Spring generates a UUIDv7. If it is malformed, Spring returns `400 INVALID_INTERACTION_ID` with a newly generated safe correlation identifier.

Every response echoes `X-Interaction-ID` and `X-Request-ID`. Traced responses also include `X-Trace-ID`. W3C `traceparent`/`tracestate` remains the propagation protocol; `X-Trace-ID` is only a support aid.

## Errors

All handled API failures use `application/problem+json` fields `type`, `title`, `status`, `code`, `detail`, `interactionId`, and `traceId`. Browser responses never include stack traces, SQL, database hosts, credentials, tokens, answer keys, or private learner content.

## Logging and database observations

Inbound request context places `interactionId`, `requestId`, `traceId`, `spanId`, and HTTP method into MDC. Shared and production profiles use Spring Boot's native Logstash JSON format, which includes MDC fields. Database calls are decorated by Datasource Micrometer and mapped to OpenTelemetry database-client conventions.

OTLP export is disabled until an approved collector is introduced. Instrumentation and in-process trace context remain active. Enabling export later must use environment-managed endpoints and credentials, never source-controlled secrets.

The temporary `/api/v1/system/database-probe` endpoint exists to prove the UI-to-API-to-JDBC correlation path. M0-T04 must restrict it to an appropriate authenticated operational role or replace it with the finalized secured readiness contract.

## Investigation

1. Obtain `interactionId` from the UI error or response.
2. Search structured logs for every associated `traceId`.
3. Open the failed trace and identify its component/JDBC span.
4. Correlate the safe `errorCode` and operation name.
5. Inspect idempotency and durable provenance before retrying a consequential write.
